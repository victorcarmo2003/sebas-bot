6. Admin API

A REST API que o painel usa pra falar com o core. Só relevante pra você, autor de módulo, se seu módulo tiver controller — é o mesmo mecanismo por trás.

Autenticação

Toda rota (prefixo /api/admin) exige dois headers:

authorization: Bearer <ADMIN_API_SECRET>
x-admin-discord-id: <discord user id de quem esta chamando>

O secret é compartilhado entre core e painel (mesma máquina/confiança); o segundo header identifica o admin pra checagem de escopo (dono vs. subadmin com permissões específicas).

Rotas relevantes pra módulos

RotaO que faz
GET /modules/discover?q=Busca no GitHub por repos com sebas.module.json (code search — precisa de token do GitHub configurado).
POST /modules/install {repoUrl}Clona, builda, self-test em sandbox. Ver seção 9 do modo IA pro fluxo completo.
GET /modules/:idDetalhe completo: manifest, state, grants, eventos, diff de permissão pendente.
POST /modules/:id/approve / /rejectSó dono. Aprova ou rejeita o diff de permissões pedido.
POST /modules/:id/enable / /disableLiga/desliga a worker_thread do módulo.
POST /modules/:id/check-update / /updateCompara HEAD local vs. remoto (git ls-remote), aplica se pedido.
ALL /modules/:id/controller/*Encaminha pro handleRequest do seu módulo — req.path chega sem esse prefixo.
Não existe um SDK/cliente publicado pra essa API — o painel (packages/panel/src/lib/worker-api.ts) é a implementação de referência de como chamar cada rota.

6. Admin API

The REST API the panel uses to talk to core. Only relevant to you, as a module author, if your module has a controller — it's the same mechanism underneath.

Authentication

Every route (under the /api/admin prefix) requires two headers:

authorization: Bearer <ADMIN_API_SECRET>
x-admin-discord-id: <discord user id of the caller>

The secret is shared between core and panel (same machine/trust boundary); the second header identifies the admin for scope checking (owner vs. subadmin with specific permissions).

Routes relevant to modules

RouteWhat it does
GET /modules/discover?q=Searches GitHub for repos with a sebas.module.json (code search — needs a GitHub token configured).
POST /modules/install {repoUrl}Clones, builds, sandboxed self-test. See AI mode section 9 for the full flow.
GET /modules/:idFull detail: manifest, state, grants, events, pending permission diff.
POST /modules/:id/approve / /rejectOwner-only. Approves or rejects the requested permission diff.
POST /modules/:id/enable / /disableStarts/stops the module's worker_thread.
POST /modules/:id/check-update / /updateCompares local vs. remote HEAD (git ls-remote), applies if requested.
ALL /modules/:id/controller/*Forwards to your module's handleRequest — req.path arrives stripped of this prefix.
There's no published SDK/client for this API — the panel (packages/panel/src/lib/worker-api.ts) is the reference implementation of how to call every route.
