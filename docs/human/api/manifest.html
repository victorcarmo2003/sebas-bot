1. Manifest

sebas.module.json, obrigatório na raiz do repositório do módulo.

Schema completo

interface SebasModuleManifest {
  schemaVersion: 1;
  id: string;                    // slug estável, ex. "changelog-roblox"
  name: string;                  // nome de exibição
  description?: string;
  version: string;               // seu próprio semver
  sebasCompat: string;           // ex. "^1.0.0" — core hoje anuncia "1.0.0", só o MAJOR precisa bater
  repoUrl: string;                // URL de clone do seu repo (https)
  capabilities: ModuleCapability[]; // sessão 3
  entryPoints: Record<string, string | undefined>; // nome da capability -> "dist/xxx.js"
  cron?: { schedule: string; timeoutMs?: number };  // só se capabilities incluir "cron"
  discordCommands?: { commands: string[] };          // só se capabilities incluir "discordCommands"
  webhook?: { publicPath: string };                  // declarado, não implementado — não confie nisso
  permissions?: {
    adminScopes?: string[];
    providesScopes?: string[];
    network?: { domains: string[] };     // hostnames exatos que ctx.fetch pode chamar
    storage?: { kind?: "kv" | "sql"; maxMb: number };
    discordPermissions?: string[];       // "send-messages" | "edit-interactions" (únicos dois checados hoje)
  };
  dependencies?: { aiProvider?: string }; // "core" = usa o provedor de IA configurado pelo dono do bot
  resources: { maxMemoryMb: number };
}

ModuleCapability

"controller" | "cron" | "ui" | "discordCommands" | "tools" | "aiProvider" | "storage" | "webhook" | "permissionGate"

Atenção: "ui", "aiProvider" (como capability), "storage" (como capability) e "webhook" existem no union de tipos mas não estão implementados em lugar nenhum do core — declarar não faz nada. As cinco reais estão na sessão 3.

Exemplo real

sebas-module-changelog-roblox/sebas.module.json, resumido:

{
  "schemaVersion": 1,
  "id": "changelog-roblox",
  "name": "Changelog do Roblox",
  "version": "1.0.0",
  "sebasCompat": "^1.0.0",
  "repoUrl": "https://github.com/victorcarmo2003/sebas-module-changelog-roblox",
  "capabilities": ["controller", "cron", "discordCommands"],
  "entryPoints": {
    "controller": "dist/controller.js",
    "chronos": "dist/cron.js",
    "discordCommands": "dist/discord-commands.js"
  },
  "cron": { "schedule": "7,37 * * * *", "timeoutMs": 600000 },
  "discordCommands": { "commands": ["setup", "teste"] },
  "permissions": {
    "network": { "domains": ["robloxapi.github.io", "create.roblox.com"] },
    "storage": { "kind": "sql", "maxMb": 64 },
    "discordPermissions": ["send-messages", "edit-interactions"]
  },
  "dependencies": { "aiProvider": "core" },
  "resources": { "maxMemoryMb": 96 }
}
Repare: a chave de entryPoints pra capability cron é "chronos", não "cron". manifest.cron é a configuração do agendamento; entryPoints.chronos é o caminho do arquivo. Fácil de confundir.

1. Manifest

sebas.module.json, required at the root of the module's repository.

Full schema

interface SebasModuleManifest {
  schemaVersion: 1;
  id: string;                    // stable slug, e.g. "changelog-roblox"
  name: string;                  // display name
  description?: string;
  version: string;               // your own semver
  sebasCompat: string;           // e.g. "^1.0.0" — core currently announces "1.0.0", only MAJOR must match
  repoUrl: string;                // your repo's clone URL (https)
  capabilities: ModuleCapability[]; // section 3
  entryPoints: Record<string, string | undefined>; // capability name -> "dist/xxx.js"
  cron?: { schedule: string; timeoutMs?: number };  // only if capabilities includes "cron"
  discordCommands?: { commands: string[] };          // only if capabilities includes "discordCommands"
  webhook?: { publicPath: string };                  // declared, not implemented — don't rely on it
  permissions?: {
    adminScopes?: string[];
    providesScopes?: string[];
    network?: { domains: string[] };     // exact hostnames your ctx.fetch may call
    storage?: { kind?: "kv" | "sql"; maxMb: number };
    discordPermissions?: string[];       // "send-messages" | "edit-interactions" (only two checked today)
  };
  dependencies?: { aiProvider?: string }; // "core" = use the bot owner's configured AI provider
  resources: { maxMemoryMb: number };
}

ModuleCapability

"controller" | "cron" | "ui" | "discordCommands" | "tools" | "aiProvider" | "storage" | "webhook" | "permissionGate"

Careful: "ui", "aiProvider" (as a capability), "storage" (as a capability) and "webhook" exist in the type union but aren't implemented anywhere in core — declaring them does nothing. The five real ones are in section 3.
