Criando um módulo

Do zero até instalado no seu Sebas — usando um módulo mínimo, só-tools, como exemplo.

Quer que uma IA escreva o módulo pra você? Manda o link do modo IA pra ela — tem a spec técnica inteira num único documento em texto plano.

1. Estrutura do repositório

seu-modulo/
  sebas.module.json
  package.json
  tsconfig.json
  src/
    sebas-types.ts   (copie as interfaces da sessão 2 da API que seu módulo usa)
    tools.ts

2. package.json

{
  "name": "sebas-module-dice-roller",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "scripts": { "build": "tsc -p ." },
  "devDependencies": { "typescript": "^5.7.0", "@types/node": "^22.10.0" }
}

3. tsconfig.json

{
  "compilerOptions": {
    "target": "ES2023", "lib": ["ES2023"],
    "module": "NodeNext", "moduleResolution": "NodeNext",
    "outDir": "dist", "rootDir": "src",
    "strict": true, "esModuleInterop": true,
    "forceConsistentCasingInFileNames": true, "skipLibCheck": true,
    "types": ["node"]
  },
  "include": ["src/**/*.ts"]
}
Toda import relativa no seu .ts termina em .js, mesmo o arquivo fonte sendo .ts — comportamento padrão do NodeNext, não é peculiaridade do Sebas, mas pega muita gente.

4. sebas.module.json

{
  "schemaVersion": 1, "id": "dice-roller", "name": "Dice Roller",
  "version": "1.0.0", "sebasCompat": "^1.0.0",
  "repoUrl": "https://github.com/voce/sebas-module-dice-roller",
  "capabilities": ["tools"],
  "entryPoints": { "tools": "dist/tools.js" },
  "resources": { "maxMemoryMb": 32 }
}

5. src/tools.ts

import type { SebasModuleContext, SebasModuleTools } from "./sebas-types.js";

const tools: SebasModuleTools = {
  tools: [{
    name: "roll_dice",
    description: "Rola um dado de N lados e devolve o resultado.",
    parameters: { type: "object", properties: { sides: { type: "number" } }, required: ["sides"] }
  }],
  async callTool(ctx: SebasModuleContext, name, args) {
    if (name !== "roll_dice") return { ok: false, error: "unknown tool" };
    const sides = Number((args as { sides: unknown }).sides) || 6;
    return { ok: true, result: { rolled: 1 + Math.floor(Math.random() * sides) } };
  }
};
export default tools;

Sem storage, sem rede, sem permissão de Discord — o manifest não declara nada além de tools, então é isso que ele recebe.

6. Build, publique, instale

  1. npm install && npm run build localmente pra conferir que compila.
  2. Suba num repositório público no GitHub com sebas.module.json na raiz.
  3. No painel do seu Sebas: /modules/marketplace, cole a URL do repo (ou deixe a busca achar), clique "Clonar e validar".
  4. Revise o diff de permissões (nesse exemplo, nenhuma) e aprove.
  5. Habilite. Pronto — a tool module:dice-roller:roll_dice já aparece pra IA na próxima conversa.

Quer algo mais completo?

Os dois módulos de referência cobrem os outros quatro casos:

  • sebas-module-changelog-roblox — controller (tela própria no painel) + cron (polling periódico) + discordCommands + sql + rede externa + IA.
  • sebas-module-permissions — controller + permissionGate, sem rede nem IA.

Checklist rápido

  • Toda import relativa termina em .js.
  • entryPoints.chronos, não entryPoints.cron.
  • selfTest() só pode depender de ctx.storage.
  • Todo hostname que ctx.fetch chama está em permissions.network.domains.
  • ctx.ai pode ser null — sempre cheque antes de .run().
  • "ui" / "aiProvider" / "storage" (como capability) / "webhook" não fazem nada — não conte com eles.

Creating a module

From nothing to installed on your Sebas — using a minimal, tools-only module as the example.

Want an AI to write the module for you? Send it the AI mode link — it has the entire technical spec in one plain-text document.

1. Repository layout

your-module/
  sebas.module.json
  package.json
  tsconfig.json
  src/
    sebas-types.ts   (copy the interfaces from API section 2 your module uses)
    tools.ts

2. package.json

{
  "name": "sebas-module-dice-roller",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "scripts": { "build": "tsc -p ." },
  "devDependencies": { "typescript": "^5.7.0", "@types/node": "^22.10.0" }
}

3. tsconfig.json

{
  "compilerOptions": {
    "target": "ES2023", "lib": ["ES2023"],
    "module": "NodeNext", "moduleResolution": "NodeNext",
    "outDir": "dist", "rootDir": "src",
    "strict": true, "esModuleInterop": true,
    "forceConsistentCasingInFileNames": true, "skipLibCheck": true,
    "types": ["node"]
  },
  "include": ["src/**/*.ts"]
}
Every relative import in your .ts ends in .js, even though the source file is .ts — standard NodeNext behavior, not a Sebas quirk, but it trips a lot of people up.

4. sebas.module.json

{
  "schemaVersion": 1, "id": "dice-roller", "name": "Dice Roller",
  "version": "1.0.0", "sebasCompat": "^1.0.0",
  "repoUrl": "https://github.com/you/sebas-module-dice-roller",
  "capabilities": ["tools"],
  "entryPoints": { "tools": "dist/tools.js" },
  "resources": { "maxMemoryMb": 32 }
}

5. src/tools.ts

import type { SebasModuleContext, SebasModuleTools } from "./sebas-types.js";

const tools: SebasModuleTools = {
  tools: [{
    name: "roll_dice",
    description: "Rolls an N-sided die and returns the result.",
    parameters: { type: "object", properties: { sides: { type: "number" } }, required: ["sides"] }
  }],
  async callTool(ctx: SebasModuleContext, name, args) {
    if (name !== "roll_dice") return { ok: false, error: "unknown tool" };
    const sides = Number((args as { sides: unknown }).sides) || 6;
    return { ok: true, result: { rolled: 1 + Math.floor(Math.random() * sides) } };
  }
};
export default tools;

No storage, no network, no Discord permission — the manifest declares nothing beyond tools, so that's all it gets.

6. Build, publish, install

  1. npm install && npm run build locally to confirm it compiles.
  2. Push to a public GitHub repo with sebas.module.json at the root.
  3. In your Sebas panel: /modules/marketplace, paste the repo URL (or let search find it), click "Clone and validate".
  4. Review the permission diff (none, in this example) and approve.
  5. Enable it. Done — the module:dice-roller:roll_dice tool shows up for the AI on the next conversation.

Want something more complete?

The two reference modules cover the other four cases:

  • sebas-module-changelog-roblox — controller (own panel screen) + cron (periodic polling) + discordCommands + sql + external network + AI.
  • sebas-module-permissions — controller + permissionGate, no network or AI.

Quick checklist

  • Every relative import ends in .js.
  • entryPoints.chronos, not entryPoints.cron.
  • selfTest() can only depend on ctx.storage.
  • Every hostname ctx.fetch calls is in permissions.network.domains.
  • ctx.ai can be null — always check before .run().
  • "ui" / "aiProvider" / "storage" (as a capability) / "webhook" do nothing — don't rely on them.
